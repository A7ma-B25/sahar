# Sahar 0.13 — live activities Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sahar carries what is going on (music, weather, Claude Code, her shelf, the PC, while-you-were-away, file
copies, screen time) as a porcelain tag on a thread under her, opens a card for it on a click, says moments in her
bubble, and shows them in her face.

**Architecture:** Every rule lives in `Sahar.Core/Activities` (pure, unit-tested): the stack (rank, moments, beads,
wheel), the tag's place, the fullscreen/knock matrix, and each source's logic (weather alerts, media, lyrics, Claude
hooks, copy pace, away log, screen time). The engine adds thin `Sahar.Engine/Activities` pieces: one hub that feeds
the stack from the senses, the tag and its input window, the card (the 0.11 card frame with a new painter), the knock
window, and the per-source readers. The settings app gets the «النشاطات» page last, on top of the final 0.12.

**Tech Stack:** C# / .NET 10 Native AOT, Windows.UI.Composition + Direct2D/DirectWrite (raw vtables), CsWinRT
projections (GSMTC, BitmapDecoder, Ocr, Battery), xunit v3; WebView2 page (vanilla JS) for settings; PowerShell UI
stage on GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-13-sahar-0.13-activities-design.md` (the Owner rulings at its end bind).

## Global Constraints

- Owner rulings: the tag she carries (direction 1); all four extras; Claude Code is **notify-only** (no Allow/Deny,
  Sahar never answers; the hook never prints a decision); weather falls back to the prayer city.
- Tag: `menu` token, radius 14, height 40, max width 220, Rubik 13/500, one line + ellipsis, 5 px eyelet, 1.5 px
  thread (`boundary`), icon or 24 px cover, optional meta (tabular digits), optional 2 px progress line.
- Card: 296 wide, padding 8, radius 22, header radius 14, the menu's shadow; placed by `MenuCardLayout.Place`.
- Rank (high→low): ClaudeAsk; moments (6 s; volume 1.5 s); copy/timer; Claude working; music; camera/mic; shelf;
  music paused (10 min default); weather today (only when nothing else). Equal rank: newest first. Beads ≤ 3 then a knot.
- Knock (fullscreen on her monitor): Claude asking, storm/gale/heat, battery low; 4 s from the top edge; no buttons.
- Network only: weather (Privacy → الطقس) and lyrics (opt-in, off by default, lrclib.net only).
- Logs: kinds and counts only — never song titles, artists, file names/paths, commands, URLs, typed text, window
  titles, city names, user name.
- Overlay: the tag never needs a monitor-covering window (`OverlayPlan.Uncover`); visuals show only once the stage
  settled. Shell, face and menu-open stages stay green.
- Version stays as is; notes go under a 0.13 heading in `packaging/README-test-build.txt`.

## Review Focus

1. Two Claude Code sessions at once — one asking, one working: the ask stays first until *its* session moves on;
   the other's Stop never clears it. (Task 3: `ClaudeBoard_DoneInOtherSession_KeepsAsk`.)
2. Hook stdin that is not JSON, empty, or huge (a 5 MB `tool_response`): the hook exits 0 at once with empty stdout
   and the pipe gets at most one short line. (Task 3: `HookRun_Garbage_ExitsZeroSilently`, `Signal_ArgsAreShort`.)
3. `~/.claude/settings.json` missing, empty, invalid JSON, or holding other hooks: linking never overwrites an
   unreadable file and never touches entries that are not ours. (Task 3: `Install_InvalidJson_Refused`,
   `Install_KeepsOtherHooks`.)
4. Weather on with no weather city but a prayer place from Windows location; or neither city: the label says
   «نفس مدينة الصلاة: موقع الويندوز»; with neither, nothing is fetched. (Task 2: `City_*`.)
5. A shelf file deleted after it was dropped, or a screenshot still being written: the item drops out; the screenshot
   waits for a stable size. (Task 2: `Shelf_MissingFilesDropOut`, `Settle_GrowingFileWaits`.)
