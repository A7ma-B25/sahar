# Sahar 0.10c — The Settings App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Sahar.Settings.exe` — a separate program opened from her menu, a WebView2 page in a plain Win32 window, where every change applies at once to Sahar and to a living SVG Sahar in the page; it never touches the network and fully exits when closed. Ends with test build 0.10.0.

**Architecture:** The page (static HTML/CSS/JS, Rubik self-hosted, served from the virtual host `https://sahar.settings/`) talks to the host with `postMessage`. The host is thin: a Win32 window, a WebView2 controller and `SettingsBridge` — a Core class (unit-tested on Linux) that reads and writes `settings.json` through `SettingsStore`, validates every edit with `SettingsPatch`, and tells the engine over the existing `sahar` pipe (`settings-reload`, `city-search`, `shortcut-try`, `clipboard-clear`, `erase-all`). The engine re-applies settings live and hops. The preview SVG is exported from `tools/art/design.py`; its motion is a JS port of 0.10a's `SoulMath` checked against the same numbers.

**Tech Stack:** .NET 10 (`net10.0-windows10.0.22621.0`, not AOT, self-contained single file) + `Microsoft.Web.WebView2` 1.0.4314.35 (Core API only, no WinForms/WPF); Win32 via `LibraryImport`; DWM; `Windows.Devices.Geolocation`; plain ES modules (no bundler, no npm packages); Node 22 `node --test` for pure JS; Python 3 for the SVG export; impeccable detector; PowerShell UI stage `settings`.

**Spec:** `docs/superpowers/specs/2026-11-08-sahar-look-menu-settings-design.md` §2, §6, §7, §8, §9 (items 4–7). Layout and copy: `/home/claude/sahar-design/project/PSettingsSoul.dc.html` (light/dark values and Arabic copy copied below); UI study `docs/design/2026-11-08-sahar-design-study.md` §3.2, §5, §7.

**Depends on:** 0.10a (`SoulMath` numbers, `SoulLayer.Hop/HappyFace`, `Rig.Sky`, `SaharSettings.InnerStars`, `SaharVisual.SetInnerStars`) and 0.10b (`SaharSettings` menu fields + `Appearance`, `MenuCatalog.ItemIds`, `Shortcuts.Check/Taken`, `Tokens`, `Digits`, `MenuCard.Reload`, `Hotkey.TryRegister`, `SettingsLauncher`, `Theme.AppsDark`, Rubik download URL).

## Rulings

1. **Two of the nine pages are hidden in 0.10:** الأصوات (no sound exists yet; every control would do nothing) and Claude Code (linking is not built). The page registry keeps all nine with an `available` flag, so the sidebar shows سحورة · القائمة / الصلاة · الاستماع / عام · الخصوصية / حول. — Why: the owner's hide rule outranks the page list. Cost if wrong: two flags plus their controls. **Owner to confirm.**
2. **Controls without a working feature are hidden too:** study §3.2's digits, start-with-Windows, seasonal icon, check-for-updates, reciter preview (it would stream from the network inside the settings app), "show the song playing", blocked apps (the field exists but nothing reads it). — Cost: small each.
3. **The "by herself" switches need two new fields:** `AutoMood` (bool, true — she posts her late-night mood) and `PlaysAlone` (bool, true — life may choose `PlayWithMoon`, `HopWindows`, `MoonToss`, `ChaseButterfly`); and the reminder switch needs `PrayerReminderOn` (bool, true). `AwarenessEnabled` (exists, unread today) now gates her comments. `InnerStars` gets a switch «النجوم جواتي» in a small «شكلي» group on سحورة (the field exists only to be set here). — Cost: three fields.
4. **No lost updates between the two writers:** both processes save with `SettingsStore.Update(path, s => s with { … })` (load → change → atomic replace), never by writing a whole in-memory copy. — Cost: one helper, ten call sites in the engine.
5. **City search goes through the engine** (`city-search` → its Open-Meteo geocoder), so the settings app itself never opens a socket. Without the engine running, the search row says «شغّلني أول لدوّر عالمدينة.». "Windows location" uses the OS `Geolocator` in the settings app (an OS service, not a page request) and stores the coordinates with the city label «موقع الويندوز».
6. **The settings app is self-contained single-file** (users of the test build have no .NET runtime): `Sahar.Settings\Sahar.Settings.exe` + `web\` next to `Sahar.Engine.exe`; the zip grows by roughly 30 MB compressed. **Owner to know.**
7. **The preview is always Calm** (the settings app has no mood) and moves with the same maths as the engine, run by `requestAnimationFrame` only while the page is visible and motion is allowed.
8. **Her words to you in the page follow your gender** with the same whole-word pairs as `Address` (the host sends `Address.Pairs`), so «اكتب اسمك» becomes «اكتبي اسمك».
9. **"Erase all my data"** = the engine deletes `%AppData%\Sahar\*` and quits; the settings app restarts it and says «مسحت كل شي. رح نتعرّف من جديد.» — Cost: one command.

## Review Focus

1. **Both programs write `settings.json`** (you choose a city in her menu while the settings app is open; she saves the activity from the tray): neither change is lost, and the page shows the newer value after its next `get` (on focus). → Task 1 `Update_*` tests; Task 8 UI step "two writers".
2. **The engine is not running** (closed, crashed, starting): every change still saves; pipe calls fail quietly within 1 s; the page shows the city-search hint; nothing throws. → Task 3 `Bridge_WithoutEngine_*` tests; Task 8 UI step "settings without her".
3. **A second launch** while the window is open brings that window to the front and exits; closing never leaves `msedgewebview2.exe` processes of ours behind. → Task 3 UI steps.
4. **WebView2 missing or failing** (no runtime, a locked user-data folder): a short Arabic message (`MessageBox`, not in test mode), exit code 2, no crash dialog; the engine hides «إعداداتي» when the runtime is missing (0.10b). → Task 3 UI step with `--webview-data <a file path>`.
5. **Anything trying the network from the page** (a stray Google Fonts link, an `<img src="https://…">`, a navigation): blocked with a 403 and counted; the count stays 0 after visiting every page. → Task 4 `no-network` node test; Task 8 UI step `blocked=0`.
