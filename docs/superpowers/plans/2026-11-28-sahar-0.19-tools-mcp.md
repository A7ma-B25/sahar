# Sahar 0.19 — tools and MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline, TDD RED→GREEN, ledger in
> `.superpowers/sdd/2026-11-28-sahar-0.19-tools-mcp/progress.md`). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Sahar uses tools he gives her — MCP servers he adds on «الأدوات» (a «رابط» or a local «برنامج» .exe) and two
built-in media tools (`image.make`, `voice.make`) — each visible, approved by him, isolated, and unable to talk her into
anything.

**Architecture:** Core gets the pure pieces in `Mind/Tools/` (schema → `ArgSpec`, slugs, descriptor hash, sensitive
words, output sanitizer, grants, the sealed tool config with the rug-pull merge, media specs, templates) and the
TurnRunner learns *Mind-side tools* (`IMindTools`): the engine still validates and decides (ask / act / refuse) and
answers `answer{yes:true}`; the Mind then runs the call (MCP client in `Sahar.Mind/Tools`, one Job Object per stdio
server; Pollinations / Groq over HTTPS), sends `tool-out`, and may take one tool-less step over a
`<tool_output … trust=untrusted>` block. The engine shows result / image / voice cards in the chat window and taints the
turn. The settings app gets «الأدوات» through `MindBridges.Tools.cs`, mirroring «العقل أونلاين» (page → engine →
Mind `tools` → `tools-status` cached by the engine → page polls).

**Tech Stack:** C# .NET 10 (Mind and engine Native AOT; JSON source-gen / Utf8JsonWriter), NuGet
`ModelContextProtocol.Core` **2.4.0** (Sahar.Mind only, client side), xUnit, vanilla JS (node:test), PowerShell UI
harness + a C# fake stdio MCP server + a Python fake (HTTP MCP, Pollinations, Groq) on 127.0.0.1, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-28-sahar-0.19-tools-mcp-design.md` (research:
`/home/claude/sahar-design/research/2026-11-28-phase2-tools-mcp.md`).

## Global Constraints

- `ModelContextProtocol.Core` exactly `2.4.0`, referenced by `src/Sahar.Mind` only; zero IL trim/AOT warnings in the
  Mind's `dotnet publish -r win-x64` (baseline: zero, ui-test run 46088013013). Gate fails → stop and report.
- Tool choice stays in the local grammar-constrained decision JSON; native OpenAI `tools` stays off; online replies
  never run tools; tool names/schemas/args never go online to *choose* a tool.
- Class is Sahar's, never the server's annotations: MCP default B (ask); «بس بتقرا» → Read (act); sensitive
  (delete/remove/send/post/pay/buy/transfer… EN+AR, or his mark) asks **every time** and never "always" (D4); C refused.
- Tainted turn (untrusted output already in it): every further tool call asks, "always" and Read ignored; ≤ 3 Mind-side
  runs per turn; the first error ends the turn; MCP and media tools only for his own chat/voice turns (never Self).
- At most 12 MCP tools enabled at once; a tool whose `inputSchema` does not fit the `ArgSpec` subset is never announced.
- Sanitizer: strip zero-width (U+200B–U+200D, U+2060–U+2064, U+FEFF, U+180E), tag block U+E0000–U+E007F, bidi
  embeddings/overrides/isolates (U+202A–U+202E, U+2066–U+2069) and C0/C1 controls except `\n`/`\t`; keep Arabic and
  LRM/RLM/ALM; cap 4 000 chars; non-text dropped except images (shown, never fed to the model).
- Timeouts: MCP call 30 s, media 90 s; cancelled when the turn is cancelled.
- stdio servers: a local `.exe` only (no Node/Python, no cmd.exe), own Job Object (kill-on-close, 512 MB process
  memory), working folder = its own folder, SHA-256 recorded; changed file → paused until he approves.
- HTTP servers: `https://…` or `http://127.0.0.1|localhost|[::1]` only; no redirects; OAuth servers → «مو مدعوم بعد».
- Secrets (header value or env value): typed once, sealed with DPAPI in her box (`tools-secrets`), given only to that
  server, never logged, never sent back to the page.
- Media: Pollinations `https://image.pollinations.ai/prompt/<escaped prompt_en ≤ 300>`; 402 + `Retry-After` → she says
  the seconds, no retry, no queue. Groq `audio/speech`, model `canopylabs/orpheus-arabic-saudi`, text ≤ 200 chars,
  existing Groq key; files `Pictures\Sahar\sahar-image-yyyyMMdd-HHmmss.png` / `sahar-voice-yyyyMMdd-HHmmss.wav`. Each media
  tool hidden (not announced, no UI action) until its provider check passed once; no Groq key → voice not announced.
  Video: nothing anywhere.
- CI never calls real Pollinations/Groq/MCP endpoints: `SAHAR_MIND_ONLINE_BASE` (loopback only) stands in for both
  media hosts (`<base>pollinations/…`, `<base>groq/…`).
- Logs and `perf.txt`: server index, tool name, class, verdict, duration, ok/error code only — never args, outputs,
  prompts, titles, typed text, file names, paths, URLs or the user name.
- UI: Syrian Arabic, short; Porcelain look, RTL, light + dark; buttons for what does not work are hidden, not greyed.
- Version 0.19.0. Never publish, never touch `main`. Commits end with the two attribution lines.

## Review Focus

1. A server whose `tools/list` changes between enable and call (rug pull) — the call never runs, the tool shows
   «بدها موافقة جديدة», nothing is announced for it (`McpCatalogTests.Merge_ChangedDescription_QuarantinesEnabledTool`
   + Mind re-lists before each call: UI step "a changed description is quarantined").
2. Tool output with hidden instructions (zero-width, tag chars, RLO, a fake `</tool_output>`) — stripped/neutralised,
   the next call in that turn asks even if "always" (`ToolOutputTests.*`, `AutonomyPolicyToolTests.Tainted_*`,
   `TurnRunnerToolTests.SecondCallAfterOutput_IsTainted`).
3. An `.exe` that hangs, floods stdout or eats memory — the 30 s timeout ends the turn with a plain line, the Job Object
   kills it at 512 MB, nothing of it outlives the Mind (UI steps "memory cap", "kill on Mind exit").
4. A server name in Arabic only / two servers with the same name / a tool name with dots or spaces — a unique `[a-z0-9_]`
   slug, `mcp.<slug>.<tool>` names never collide, odd tool names are not announced (`McpSchemaTests.Slug_*`).
5. The 13th enable, or enabling a changed/unfit tool from a stale page — refused with a plain line, config unchanged
   (`McpCatalogTests.Enable_*`).
