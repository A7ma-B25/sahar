# Sahar 0.14 — her local brain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sahar thinks on his PC: a bundled llama-server runs any GGUF model he picks (Gemma 4 E4B by default), she
chats and acts through typed tool calls under a policy in code, speaks on her own often but never at the wrong time,
learns him only from what he allows and confirms, and drafts in his voice without ever sending.

**Architecture:** Three parallel streams on three branches meet at the seams committed in `54cf0d5`
(`src/Sahar.Core/Mind/**` contracts, `MindParts`, `MindBridges`, `MindEngine`, the `mind` UI stage files). Every
decision lives in `Sahar.Core` and is unit-tested on Linux; `Sahar.Mind.exe` (AOT) hosts the runtime and the turn loop;
the engine and the settings app only wire. Stream A (lead, `feat/0.14-brain`) integrates B and C at the end.

**Tech Stack:** C# / .NET 10 Native AOT, source-generated System.Text.Json, llama.cpp `llama-server` (pinned build,
Vulkan default, CPU in CI, CUDA optional), xunit v3; WebView2 settings app (vanilla JS); PowerShell UI stage on
GitHub Actions (windows-latest, CPU only).

**Spec:** `docs/superpowers/specs/2026-11-13-sahar-0.14-local-brain-design.md` — the **Owner answers** section at its
end binds and overrides the text above it. Mockups: `docs/design/brain/*.png` (canvas page «الإصدار 14 — الذكاء»).

## Global Constraints

- Owner answers bind: 32 GB RAM + RTX 4050 (design for the 6 GB laptop part); download ≈ 5 GB, reachability test
  first, plain words when Hugging Face is blocked + his VPN hint, pause/resume across restarts, SHA-256 verify,
  **never start without his yes**; learning sources: all four, **opt-in each**; initiative **often**, never while
  busy/typing hard, fullscreen, away/locked, prayer, DND; autonomy: acts alone in her reversible world, asks first for
  anything outside it, **never answers Claude Code permissions**; any model (recommended list + add by HF link/name or
  a local .gguf), each benchmarked (speed, VRAM, Arabic/dialect check, tool-call check), chat-only badge when it cannot
  tool-call, switching keeps memory; Self mode drafts with one-tap copy, **she never sends** (no send tool exists).
- Privacy: logs hold kinds, counts and timings only — never prompts, replies, chat text, titles, file names or the
  user name. Personal data only in `MindPaths.Personal`, encrypted (AES-256-GCM, key wrapped with DPAPI CurrentUser).
- Supportive techniques only; never diagnose or label; the distress reply is a fixed reviewed text; invent no help
  resources (the help card ships with «احكي مع حدا بتثق فيه» only).
- Look: Porcelain (opaque, matte, no glass or glow; only Sahar carries colour; Rubik; hand-drawn wobble icons via the
  `psHand` filter; light and dark); new pages use the existing tokens and `controls.js` parts exactly as the mockups.
- Downloads only from official pinned sources: ggml-org llama.cpp releases and Hugging Face files at a pinned commit
  with the LFS SHA-256. CI never downloads the 5 GB model.
- Version stays 0.12.0 (combined release at integration); notes under a 0.14 heading in `packaging/README-test-build.txt`
  (the lead writes them from each stream's report).
- The overlay never covers a monitor; shell, face and menu-open stages stay green.
- **Stay inside your stream's files.** A seam change is ONE commit on `feat/0.14-brain` by the lead, announced to all.

## Rulings (lead, binding for all streams)

1. The four Mind pages are their own sidebar group (2): عقلي · النماذج · عنك · شو عملت اليوم (spec §8 put two in
   group 1; four would crowd it). Mockups follow this.
2. Initiative levels: `Often` (default, 12 lines/day, base gap 20 min), `Normal` (6, 45 min), `Rare` (3, 45 min),
   `Off`. The gap doubles on each dismissal up to 4 h; any line he answers resets it.
3. Consent per learning source lives in settings.json (`mindLearnChats/Imports/Examples/Music`), not in the encrypted
   store; the store reads it through `Func<LearnConsent>`.
4. CI's tiny model: `ggml-org/gemma-3-270m-it-GGUF` Q8_0 (291,545,600 B, SHA-256 `0ef57d2c…68e3`, commit `e7647be1…`),
   inside the asked 100–300 MB band, instead of the spec's 580 MB Qwen3.5-0.8B.
5. No GitHub mirror of the model is published in 0.14 (no publishing); Hugging Face is the only model source and the
   VPN hint is the fallback (owner answer).
6. Messages drafted in Self voice are a turn with `source = "draft"`; the reply is a `draft` message the engine shows in
   the bubble with «بصوتك» and a copy button.

## Review Focus

1. Hugging Face blocked or reset mid-file, then Sahar restarted: the download resumes from the saved offset with the
   same ETag, restarts from 0 when the ETag changed, and never verifies a partial file. (A2: `Resume_EtagChanged_StartsOver`, `Resume_AcrossRestart_KeepsOffset`.)
2. A model that answers with invalid JSON or names a tool that was not announced: nothing runs, she uses the template
   line, the model is marked chat-only by the benchmark. (C3: `Turn_UnknownTool_NeverRuns`; A4: `Bench_BadToolJson_ChatOnly`.)
3. An imported WhatsApp export with multi-line messages, RTL marks, other people named like him, phone numbers and
   links: only his lines are kept, scrubbed. (B2: `WhatsApp_KeepsOnlyHisLines_MultiLine`, `Scrub_PhonesEmailsUrls`.)
4. He types fast while a self-started line is due, or a prayer is 15 min away, or fullscreen video: the gate stays
   closed and gives the rule's key. (C2: `Gate_EachNeverWhenRuleCloses`.)
5. Two writers (settings app «انسي كل شي» while the Mind writes a memory): the key is deleted first, nothing readable
   remains, the Mind's next write starts a fresh store. (B1: `ForgetAll_WhileWriting_LeavesNothingReadable`.)
