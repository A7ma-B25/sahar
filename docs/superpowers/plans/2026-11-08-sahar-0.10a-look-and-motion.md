## Rulings (ambiguities in the spec, decided here)

1. **Distances of §4 are rig units, not DIP.** Float 6 and hop peak 38 are taken in the 300-unit rig space, as in the approved `SaharOriginal` mockup (its transforms are SVG user units) and as the shadow formula needs (`rx = 62 − 0.5·height` is in rig units: a 38-unit peak gives rx 43, opacity 0.084; read as "DIP@Medium" = 76 units the shadow would vanish at 0.008). So at Medium the float is 3 DIP and the hop 19 DIP, and both scale with size. — Cost if wrong: two constants (`SoulMath.FloatUnits`, `HopPeakUnits`) ×2. **Owner confirms at the 0.10.0 release** (Task 7, with the hop-strip PNG).
2. **Follow-through sign follows the mockup:** `scaleY = 1 + 0.012·cos φ + 0.012·sin(2πt/3.6)` (she stretches while rising; the mockup's `0.012 * vy/6 * -1` with `vy = −6 cos φ`). The spec's "(−cos φ)" names the velocity term. — Cost: one sign.
3. **Star edge width scales with each star** (1.3 in the star's own units, as in the mockup where the stroke sits inside `scale(s)`). — Cost: one parameter.
4. **Wash colours (owner ruling 2026-11-10, replaces the computed table):** Calm is L2 exactly (`#8E7BE0` @0.55 → `#A897EA` @0.28 → `#CBC1F0` @0), never darkened. The other 15 moods' inner/mid stops are **one literal hex table** `WASH_STOPS` in `design.py`, exported as `sky.washStops`; outer = that mood's `bottom`. The first proposal is derived once by hand-tuned rules (inner ≈ the mood's glow, darker; mid ≈ glow) and committed as literals; the owner approves it on the 16-mood sheet `docs/design/character/06-moods-sheet.svg/.png` (Task 2) and any change is an edit of that one table. No OKLab, `ColorMath` or `NightSky.ColourAt` in C#: Core only reads the table. — Cost if the owner changes colours: one table edit + re-export.
5. **Which clocks the soul replaces:** bob, shadow breathing, blink and leaf sway become the soul; the moon lap becomes 16 s; hem flutter, halo and bud-glow breathing, star-ring spin and twinkles stay as they are (original-look features). — Cost: small.
6. **Blink randomness without CPU:** 8 gaps drawn once at start from [2.6, 6] s (seeded) form one keyframe loop (≈ 35 s). — Why: "random 2.6–6 s" and "Composition-driven" both hold. Cost: none visible.
7. **Look (owner ruling 2026-11-10):** "12 %/frame equiv." becomes **implicit animations**: `EyesLayer.Container` has an implicit 400 ms `Offset` animation and a separate `Lean` container an implicit 400 ms `RotationAngleInDegrees` animation (`cubic-bezier(0.2,0.9,0.3,1)`, from `this.StartingValue` to `this.FinalValue`). The pointer path (≤ 30 Hz) only sets the target values, and only when they changed by ≥ 0.05 units / 0.05°; no explicit animation is restarted per update. The leaf's counter-lean reads the `Lean` visual's rotation in its expression. — Cost: feel only.
8. **A tap still plays the `poked` expression** (state `poked`, as the `motion` stage checks) **and** the soul hop with the Joy face; while a hop runs, `ExpressionPlayer` does not start the `Squish` extra (the hop is the squish). `celebrate`'s squish is unchanged.
9. **The hop is baked whole (owner ruling 2026-11-10):** one keyframe animation per property (`Hop.Offset.Y`, `Hop.Scale`, `Hop.RotationAngleInDegrees`, `Props.kick`) over the full `HopSeconds` = 1.2 s, sampled from `SoulMath.Hop`/`LeafKick` (landing included) — no NaturalMotion spring hand-off and no timer. `Hopping` is a time comparison against the start tick. A test-mode `AnimationController` can pause the set at any time for pixel checks. — Cost: none visible.
10. **Settings safety lands here (Task 0f):** 0.10a adds `InnerStars` and the engine already saves settings, so the owner's two-writer rules (named mutex, sharing-violation retry, never overwrite an unreadable file) are built now; 0.10c builds `Update` on them. — Cost: one small Core task.

## Review Focus

1. **A size or DPI change in mid-hop or mid-float** (dragging her onto a 150 % monitor, `debug-display-changed`): every soul animation restarts with the new pixel values; she never ends offset or squashed. → Task 5 UI step "the soul survives a rescale".
2. **A hop asked while she is not resting** (dragged, thrown, sitting, grounded expression, sulking, a game, hidden, reduced motion): no hop starts; the tap still pokes. → Task 4 `SoulRules_CanHop_*` tests; Task 5 UI step "no hop while dragged".
3. **Reduced motion switched while she moves:** loops stop at rest values, a running hop is cut to rest, the moon rests beside her; switched back, everything resumes. → Task 6 UI step with `debug-reduced-motion`.
4. **The pointer on another monitor, far away, or exactly on her eyes:** look is zero beyond 400 DIP and at zero distance (no NaN). → Task 4 `Look_*` tests.
5. **An event face arriving during the 1.1 s Joy face** (timer done, Claude permission): when the Joy face ends she shows the event's face, not a stale one. → Task 6 UI step "the joy face gives way to the newest expression".
6. **Away when another face is showing** (music, a reminder, the Quran): away comes from the last real input (system, keyboard hook, pointer), not from her face; while away she does no own actions. → Task 0 `Presence_*` tests; UI step "away stops her own actions".
