# Sahar 0.10.1 — shell-friendly Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No Sahar window covers a whole monitor in normal use (so the shell, Now Bar and notifications stop treating her as a fullscreen app), she hides only for fullscreen on her own monitor, CI runs in ~4 parallel jobs, version 0.10.1.

**Architecture:** The overlay window stops covering the virtual screen. A pure planner (`Sahar.Core.Geometry.OverlayPlan`) turns her canvas rect, the areas features currently need (menu, game, showcase, butterfly) and the monitor rects into the overlay rect; the engine's `OverlayStage` applies it (move with `SWP_NOSIZE|SWP_NOZORDER|SWP_NOACTIVATE` while only the position changes, batched with the input window via `DeferWindowPos`) and sets `host.Root.Offset = Origin − window.TopLeft`, so every visual keeps its overlay (virtual-screen) coordinates — `sahar.Origin` never changes for a window move. The catchers cover her monitor inset by 1 px. Fullscreen hiding compares the fullscreen window's monitor with hers (`FullscreenScope`).

**Tech Stack:** C# .NET 10 Native AOT, Windows.UI.Composition, xUnit (Core), PowerShell UI tests on GitHub Actions windows-latest.

**Spec:** the owner-approved brief of 2026-11-10 (Now Bar evidence, items 1–5), carried in the controller's dispatch; its binding points are copied into Global Constraints.

## Global Constraints

- No Sahar window's rect may contain a whole monitor rect while she idles, talks, opens the menu, plays a game, runs the showcase or chases the butterfly. Grown areas are inset ≥ 1 px from any monitor they would cover.
- Moving the overlay with her: at most one batched `SetWindowPos`/`DeferWindowPos` per tick, `SWP_NOACTIVATE|SWP_NOZORDER` (+`SWP_NOSIZE` when the size is unchanged); no resize per frame in follow mode; nothing at all at rest.
- Perf budgets unchanged: working set < 60 MB at rest and after idle acts (Stage-Perf).
- Fullscreen: hide only when the fullscreen window's monitor is hers; log `fullscreen: hide|show|elsewhere (monitor N, hers M, …)` — monitor indexes and the window class, never titles.
- engine.log privacy: no window titles, typed text, clipboard text or user name. Test-only pipe commands only in test mode. PowerShell `Kv` values carry no spaces.
- CI: never download or run third-party binaries (Now Bar). Workflows stay dispatchable on branches; `stages` input keeps working.
- Version 0.10.1 in `Directory.Build.props`, `CoreInfo.Version`, `app.manifest` (0.10.1.0), `SmokeTests`, `packaging/README-test-build.txt` (Arabic + English, with a manual check for Now Bar / taskbar tools / notifications).

## Review Focus

1. Two monitors with different DPI: the small overlay crossing the seam (WM_DPICHANGED must still never resize it) — her visuals must not be clipped or scaled at the seam. Pinned by OverlayPlan tests over a two-monitor layout (Task 2); runtime only by the owner.
2. Grow/shrink moments (menu opens, game starts/ends): the window's top-left and `host.Root.Offset` change in the same UI turn; a stale DWM frame could show her offset once. Expect at most one frame; any visible jump is a finding.
3. Display change (monitor unplugged, resolution) while small or grown: the stage re-plans from the new monitor list (`debug-display-changed` step in Task 3).
4. Hidden → shown: the overlay comes back placed at her, not at a stale rect (Task 3 step "after hide/show").
5. A click on another monitor while the menu is open: the catcher covers only her monitor, so that click reaches the app under it and the menu closes by deactivation (no longer swallowed). Accepted behaviour change; the owner's manual check covers it.
