# Sahar 0.10b — The Menu Card and Chat Row Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A double-click, right-click or `Alt+S` opens an opaque "Porcelain" card beside Sahar — mood header with the one most urgent fact, a chat row that runs local commands (text, and the mic where Windows dictation works), her three tiles, four quiet tools and a footer — replacing the radial ring.

**Architecture:** Everything decidable is pure Core with unit tests: the menu catalog and visibility, card geometry and placement, keyboard movement, the header fact, the chat command parser and her replies, the colour tokens with contrast checks, shortcut validation. The engine draws the card on the existing Composition overlay with Direct2D/DirectWrite (Rubik loaded from embedded font files), keeps the invisible full-screen `MenuCatcher` for clicks and keys, and hosts one borderless Win32 EDIT in a small popup over the chat field for real text input (IME, caret, RTL).

**Tech Stack:** C# .NET 10 Native AOT, Windows.UI.Composition, raw-COM Direct2D + DirectWrite (IDWriteFactory5 in-memory font set, IDWriteTextLayout1), Win32 (EDIT, RegisterHotKey), WinRT `Windows.Media.SpeechRecognition`; xUnit v3; PowerShell UI stages.

**Spec:** `docs/superpowers/specs/2026-11-08-sahar-look-menu-settings-design.md` §2, §5, §5.1, §6 (new settings fields), §7 (tokens), §8. Visual reference: `/home/claude/sahar-design/project/PMenuSoul.dc.html` (light and dark values copied below). UI study `docs/design/2026-11-08-sahar-design-study.md` §3.1, §5.

**Depends on:** 0.10a (`2026-11-08-sahar-0.10a-look-and-motion.md`) — uses `SoulLayer.Hop(float)`, `SoulLayer.HappyFace()`, `SoulLayer.Reduced`, `ColorMath.Contrast/Lerp/Over`, `Palette`, `MotionKind`. **Consumed by** 0.10c: `SaharSettings` menu fields, `MenuCatalog.ItemIds`, `Shortcut.Check`, `Tokens`, `Digits`, `MenuCard.Reload(SaharSettings)`, `Hotkey.TryRegister`, `SettingsLauncher`.

## Global Constraints

- "The menu opens in under 100 ms" (measured in the engine from the trigger to the first frame's visuals being set up).
- Card: "296 DIP wide, padding 8, radius 22, elevation e1", "12 DIP from her body, top-aligned with her head, clamped to the work area", "Opening: 180 ms, opacity + scale 0.96→1 from the corner nearest her. Closing: 120 ms", "Hover 120 ms; press scale 0.97", "Drill-in: 160 ms crossfade". Reduced motion: opening = opacity only 100 ms, closing instant, no scale, no crossfade (study §5.5).

- Mic "shown only when a working Windows speech recognizer is available for the UI language … Otherwise it is hidden."
- "Buttons for features that don't work yet are hidden, not greyed out." — so: `settings` is hidden until `Sahar.Settings.exe` and the WebView2 runtime exist (0.10c); the Claude fact is shown but not clickable (focusing the terminal is not built).

## Rulings

1. **Item ids reuse today's action ids** so the App's `Pressed` switch and the other UI stages keep working: tiles `play` «نلعب؟», `dnd` «بسكت شوي» / «رجّعيني احكي», `hide` «بغفى شوي»; tools `timer`, `note`, `listen`, `clipboard`; `chat`; footer `settings`. `SaharSettings.MenuItems` holds these ids. The new catalog is `MenuCatalog` (a class named `MenuItems` would read as the new settings field); the old `MenuItems`/`RadialLayout` classes are deleted with the ring in Task 5. — Cost: none.
2. **`MenuItems = null` means "every available item"** (old files, and the default); the settings app writes an explicit list. — Cost if wrong: an item added later stays off for people who customised the list.
3. **Defaults not given by the spec:** `MenuHeader = Urgent`, `MenuPlace = Beside`, `Appearance = System` (mockup's first options). — Cost: a default.
4. **Header tints** (spec gives Calm only): Calm uses `#EEE8FF` / `#3A3450` exactly; other moods light = `Lerp(mid, bottom, 0.10)`, dark = `Lerp(#2A2630, bottom, 0.12)`; then, in light, mix toward white in steps of 10 % (max 9) until both `ink` and `moon` measure ≥ 4.5 (Mystic, Sleepy, Night, Dim need it). — Cost: a colour table.
5. **Arabic-Indic digits are made tabular with fixed cells.** Rubik's `tnum` covers Latin digits only (checked with fontTools: its Arabic-Indic digits are proportional, 300–639 units). The engine sets `IDWriteTextLayout1::SetCharacterSpacing(0, 0, minimumAdvance = 0.64 em)` on every digit run; header, replies and timer text use Arabic-Indic digits (as in the mockup). — Cost: one helper.
6. **Static Rubik instances** (Regular 400, Medium 500, SemiBold 600) are cut from Google Fonts' `Rubik[wght].ttf` with fontTools and embedded in the engine (DirectWrite in-memory font set; GDI `AddFontMemResourceEx` for the EDIT). — Why: variable-font instances through raw COM are riskier. Cost: ~0.6 MB in the exe.
7. **Icons are drawn clean** (path data from the mockup, stroke 1.7, round caps and joins) without the mockup's `feTurbulence` "hand" wobble — the engine has no effect graph. — Cost: a slightly less hand-drawn look; owner may ask for pre-wobbled paths later.
8. **Mic and privacy:** Windows dictation (`SpeechRecognitionScenario.Dictation`) may use Microsoft's online recognizer when "Online speech recognition" is on, which v1 §14 does not list. The mic appears only when the probe compiles the dictation constraint for the UI language; on the GitHub runner it is hidden. **Owner must decide** whether online dictation is acceptable (else keep the mic hidden; one flag). Arabic offline availability is checked on the owner's machine (manual step, Task 6).
9. **Sleep from chat** («نامي») says her reply in the speech bubble, then hides after 1.2 s (the card closes when she hides, so the header could not show it). **Empty note** («ملاحظة» alone) opens the quick-note bubble. **«مؤقت» out of 1–600** replies «بقدر شغّل مؤقت من دقيقة لـ ٦٠٠ دقيقة.» and starts nothing. **Hush fact** and **Claude fact** are not clickable.
10. **The chat placeholder** «احكي معي…» is painted by the EDIT's subclass on `WM_PAINT` when empty (no Common Controls v6 manifest change, so `TextBubble` keeps its look).
11. **Activity level leaves the menu** (study §3.1); the tray keeps it, 0.10c's settings page sets it. The `activity` UI steps move to the tray item.

## Review Focus

1. **The card at a screen edge, a corner, on a second monitor or at 150 % DPI:** fully inside her monitor's work area, beside her when there is room, never over her body. → Task 3 `Place_*` tests (4 corners × DPI 1 / 1.5, both sides); Task 5 UI corners step.
2. **Odd chat input:** empty or spaces, 500 characters, tatweel and diacritics («مُؤَقّـت»), Persian/Arabic-Indic/Latin digits, upper-case "TIMER 5", «مؤقت ٠», «مؤقت 601», a note with digits («ملاحظة اتصل ب ٥٥٥»): each gets one sensible action and reply, the note keeps its text exactly as typed. → Task 2 parser tests.
3. **Focus and activation:** clicking another app while the card is open closes it; the chat popup taking focus does not close it; after Esc the previously active window is active again; `Alt+S` while open closes it. → Task 5/7 UI steps with a test window.
4. **A broken shortcut in settings.json** ("", "Alt+", "Win+L", "Ctrl+C", a key taken by another app): no crash, no hotkey, one log line; `Alt+S` default when the field is missing. → Task 3 `Shortcut_*` tests; Task 7 UI step with a taken hotkey.
5. **Everything hidden** (all items off, mic and settings unavailable, header `None`): the card shows the header and the Esc hint only, no empty rows or gaps; keyboard focus still has somewhere to go (Esc works). → Task 3 `Layout_NothingVisible_*`; Task 7 UI step.
