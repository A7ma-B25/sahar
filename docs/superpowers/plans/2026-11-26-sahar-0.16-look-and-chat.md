# Sahar 0.16 — the new look and the chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline, TDD, ledger). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Every white Win32 surface is gone; her bubble, tag, pickers, inputs, chat, tray menu, «الدرج», «شخصية سحر»,
Quran bar and hide-and-seek match the approved «الإصدار 15 — الشكل والحكي» boards in light and dark.

**Architecture:** Two kinds of surface. (1) Web surfaces (chat, pickers, inputs, tray menu, «الدرج») run in a warm,
pre-created, hidden **surface host** — `Sahar.Settings.exe --surfaces`, started by the engine — whose windows host
WebView2 in *visual (DirectComposition) mode* so they are truly transparent (rounded 22 px corners and CSS shadows as
drawn). Engine ⇄ host: one persistent duplex pipe `sahar-surfaces`, one JSON line per message (`SurfaceMsg`).
(2) Native surfaces stay Composition + D2D in the engine: speech bubble (say/ask/list/long), tag + Quran bar, game.
«شخصية سحر» is a page of the existing settings app. Pure logic (search folding, chat store, retention, hiding spots,
warmth, persona merge, emoji scan) lives in Sahar.Core with xUnit tests.

**Tech Stack:** C# .NET 10 (engine Native AOT; settings/host self-contained + WebView2 1.0.4314.35 CompositionController),
DirectComposition COM interop, vanilla JS + CSS from the mockups, PowerShell UI harness, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-20-sahar-0.15-look-and-chat-design.md` (Owner rulings 1–12 binding).
Mockups: `/home/claude/sahar-design/project/V15*.dc.html`, renders `/home/claude/sahar-design/renders/0.15/`.

## Global Constraints

- Porcelain tokens exactly as spec §2 (light/dark); Rubik 15/17-600/13; motion 220 ms cubic-bezier(.2,.9,.3,1) in, 150 ms out; reduced motion off.
- Emoji ARE allowed in her speech (ruling 3 reversed 2026-11-26); nothing strips them; surfaces render them in colour (Segoe UI Emoji). UI icons are drawn SVG.
- Chat: he left, she right (ruling 1); history local, SecretBox-encrypted, `MindEpisodeDays` retention (default 30), wiped by «انسي كل شي» (ruling 2).
- Logs: kinds, counts, lengths, ids only — never titles, chat text, file names, city or user name.
- Overlay rules hold: the overlay never covers a monitor; nothing shows before it settles; she stays topmost.
- Every window respects capture exclusion (0.15.0's «اسمح بتصويرها»; `--capturable` in test mode).
- Tray menu one language (app language), weather an explicit on/off toggle with the city, no «(اسمي)» (ruling 9).
- Web surfaces open < 150 ms from warm (measured by the host, asserted in CI with slack).
- Version 0.16.0, short Arabic notes. No push to main, no publish.

## Review Focus

1. Surface host dead or WebView2 missing: a picker request must not hang her — the engine respawns once, then says a calm line; tests: `SurfaceClient_HostGone_FailsFast` (Core fake) + ui step kills the host and opens the Quran picker.
2. A second monitor / 150 % DPI / her at a screen edge: panels clamp inside the work area of her monitor, same side rules as the card; Core `PanelPlacement` tests at both edges and both DPIs.
3. Arabic search with tashkeel, hamza forms, ة/ه, ى/ي, Arabic-Indic digits: `ArabicFold` tests incl. «٣٦», «36», «يس», «يٰسٓ».
4. «انسي كل شي» while the chat is open or the box is locked: no crash, window empties, files gone, key first; `ChatStore` tests with a locked fake box.
5. A window she hides behind moves/closes mid-round, or the pointer sits on top of every spot: `HideSeek.Spots` never returns an off-monitor/under-fullscreen/near-pointer spot, falls back to edge spots.
